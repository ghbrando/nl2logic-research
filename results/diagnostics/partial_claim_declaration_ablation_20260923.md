# Isolated declaration and prior-logic ablation — 23 September 2026

The development-only [provisional declaration registry](../../data/benchmarks/fm2-0/chapter1-partial-claim-development-source/provisional_declarations.json) admits three AI-reviewed sense-specific class names, while keeping their subclass assertions out of the background ontology. It requires a matching source cue and offers the same two existing parent-class candidates (`Process` and `IntelligenceProduct`) to each matched case. This is an **oracle vocabulary probe** informed by the chapter 1 development labels, not an independent source-only evaluation. The full supporting sentence is provided to the model encoder; the input gate remains on the exact extracted head. The run used no target labels during inference and no training.

The [saved paired CPU predictions](partial_claim_memory_cpu_20260923_declarations/predictions.jsonl), [manifest](partial_claim_memory_cpu_20260923_declarations/manifest.json), and [strict scoring](partial_claim_memory_cpu_20260923_declarations/scoring/summary.json) cover the same 14 chapter 1 development paragraphs. Eleven have no matched declaration and do not generate. Each of the other three generates in both the no-memory and retrieved-memory arms.

| Paragraph | No-memory output | Retrieved-memory output | Provisional AI-reviewed formula |
| --- | --- | --- | --- |
| 1-79 | `Source subclass-of IntelligenceProduct` | `Source subclass-of OpenSourceIntelligenceProduct` | `OpenSourceIntelligenceProduct subclass-of IntelligenceProduct` |
| 1-88 | `TechnicalIntelligenceProduct subclass-of Process` | `Process subclass-of TechnicalIntelligenceProduct` | `TechnicalIntelligenceProduct subclass-of IntelligenceProduct` |
| 1-93 | `BiometricsProcess subclass-of Process` | Same | `BiometricsProcess subclass-of Process` |

All six outputs compile as closed, argument-kind-valid KIF **when the provisional symbol declarations are supplied**. Only the biometrics output matches the provisional AI-reviewed formula, in both arms. Memory changed the two intelligence outputs without improving either. `Source` in 1-79 is an incidental ontology term picked up from “open-source”; the 1-88 memory arm reverses the subclass direction. These are concrete examples of why a valid logic string is not yet a source-supported claim.

The existing production grounding gate rejects all six outputs: the wrong intelligence formulas are weakly grounded, and even the biometrics match receives `unverified_scope` because the gateway does not yet recognize the isolated process-sense declaration as source-grounded. The matching biometrics result therefore remains a **provisional AI-reviewed development observation**, not an automatically accepted fact or independent accuracy estimate. The declaration registry itself contains no claim formula or parent assertion; however, its selected class names, source cues, and shared parent pool were informed by the reviewed examples and make this an upper-bound diagnostic.

The next implementation task is a declaration-aware, provenance-preserving grounding review that can verify a new symbol’s source phrase and sense **without** treating its declaration or retrieved axioms as proof of the subclass relation. Decoder constraints also need to block incidental terms such as `Source` and unsupported direction changes. Only after those rules are fixed on development data should we run a paired memory test on new, unseen passages with separate prior accepted claims. No training is warranted by this small probe. It ran in the project-owned rootless CPU container on worker `192.168.94.13`; the user GPU inference service was left untouched.
