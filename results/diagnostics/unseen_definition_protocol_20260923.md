# Unseen definition memory comparison protocol — 23 September 2026

This protocol was committed **before** any chapter 3+ text was extracted or read. The gate, decoder constraint, proposer, and scoring code were frozen at the same commit.

1. **Sources.** Run `scripts/build_unseen_definition_sources.py` on `src/data/ARMY FM_2-0.pdf`. It selects every numbered paragraph in chapter 3 or later where the frozen `extract_paragraph_candidate` finds a copular definition head with no input-gate reasons. It excludes first sentences overlapping chapter 1, chapter 2, or seed sources. Chapter 1 is development data and chapter 2 has already been queried, so neither is used. No labels, predictions, or manual selection are involved.
2. **Declarations.** Run `scripts/propose_declarations.py` on those sources alone. It uses the fixed parent pool `Process` and `IntelligenceProduct`, plus an existing class named exactly by the head noun. Phrases that already name an ontology class get no new declaration and do not generate.
3. **Labels.** Write provisional AI-reviewed labels (`split: eval`, `label_status: ai_reviewed_frozen_pre_target_query`) for every selected passage. Validate them with `scripts/validate_claim_packet.py` and commit them with their hash before any model query. The labels judge whether the source entails `<proposed symbol> subclass-of <parent>` for any existing class, independently of the gate's genus table. They are not expert gold. The reviewer also wrote the gate.
4. **Memory.** Prior accepted claims are the rules-arm claims accepted by the gate in the separate development run: `results/diagnostics/partial_claim_definition_gate_cpu_20260923/scoring/scored.jsonl`. The retrieved arm receives up to one ontology statement and up to one prior accepted claim as encoder context only. Neither can count as grounding evidence.
5. **Run.** The rules-only, no-memory, and retrieved-memory arms run in one CPU job, as in development, using adapter `diagnostic-closed-7k-20260922-01` with no training.
6. **Report.** For each arm: gate-accepted outputs, accepted outputs matching the provisional label (exact KIF), accepted outputs not matching (unsupported acceptances), abstentions, and the number of outputs memory changed. With small counts, report the per-passage table rather than rates. No rule changes are made after seeing unseen outputs. Any needed fixes are recorded as findings for the next development cycle.
